## 기본값 복원·상단 이동·설치 자동 실행·업데이트 (2026-11-27)

- 배경/글자 색상 선택창의 기본값 복원, 환경설정 전체 기본값 복원을 추가했습니다. 저장 전에는 원본 설정·기존 메모에 적용하지 않습니다.
- 좁은 이동 손잡이를 제거하고 제목·상단 빈 공간을 끌어서 이동합니다. 제목 두 번 클릭 또는 키보드 Enter/F2로 편집하며 Enter/Escape·포커스 이동으로 편집을 마칩니다.
- 설치 완료 화면의 자동 실행 체크박스는 기본 체크입니다. 설치 선택은 Run 등록과 HKCU32의 일회성 표식으로 반영하고, 앱은 이전 설정의 꺼짐 값을 설치 선택으로 갱신합니다. 설정 저장 성공 후에만 표식을 지우며 이후 직접 끈 설정은 유지합니다. 자동 실행 등록 확인·실패 안내도 추가했습니다.
- 동일 AppId/설치 경로를 유지하고 Restart Manager로 실행 중 앱의 정상 종료를 요청하도록 설정했습니다. 강제 종료를 요청하지 않으며 기존 메모·설정 파일을 설치 교체 대상으로 삼지 않습니다. 설치 완료 화면 배치, 업데이트 설치, 정상 종료/저장 실패, 실제 로그인 자동 실행은 아직 실기 검증하지 않았습니다.
- 최종 x86/x64 로컬 Framework MSBuild Release 빌드 성공, 콘솔 회귀 테스트 각각 **28 통과 / 0 실패**. 설치 선택 유무·체크 해제·이전 꺼짐 설정 처리, 양쪽 색상 초기화, 전체 설정 초기화와 저장 전 원본 보존, 제목 편집 전환·포커스 종료를 검사했습니다. 격리 창의 메모·색상·환경설정 PNG를 생성했습니다.
- VS MSBuild `/restore`는 x86/x64 모두 사용자 NuGet.Config 폴더 접근 거부로 실패했습니다. 공식 참조 어셈블리·Sonar 분석은 미검증입니다. `scripts/package.ps1`은 포함할 .NET 4.8 설치본 다운로드 서버 연결 실패로 중단되어 **새 설치 EXE는 생성하지 못했습니다**. Inno 스크립트 컴파일 및 Windows 7/10/11 실기 검증은 미완료입니다. 사용자 자동 실행 레지스트리와 Explorer·시스템 설정은 자동 테스트에서 변경하지 않았습니다. [추가 수동 검사 항목](compatibility.md)을 따릅니다.

## 일반 모드 기본값 보정·투명도 1% 간격 (2026-11-27)

- 이전 Desktop 기본값이 저장된 설치에서도 적용되도록 첫 실행 시 기존 설정과 메모의 표시 모드를 Normal로 한 번 전환합니다. `normalModeDefaultApplied` 선택 필드로 적용 여부를 저장합니다. 이후 사용자가 직접 고른 모드는 다음 실행에서도 유지되며 Shell fallback은 요청 모드를 변경하지 않습니다. 손상/미래 스키마로 저장이 차단된 경우에는 전환하지 않습니다. 예전 백업 복원도 동일한 일회성 전환을 적용합니다.
- 메모 하단과 환경설정의 투명도는 30~100% 범위에서 TickFrequency·SmallChange를 0.01로 지정해 마우스 스냅과 방향키 모두 1%씩 변경합니다.
- x86/x64 로컬 Framework 빌드 및 콘솔 회귀 테스트 각각 **28 통과 / 0 실패**. 기존 모드의 일회성 전환·재저장·이후 선택 유지와 양쪽 슬라이더 간격을 검사합니다. VS MSBuild `/restore`는 여전히 사용자 NuGet 폴더 접근 거부로 실패했습니다. 설치 파일 생성 및 OS 실기 검증은 미완료입니다. 로그: `TestResults/ux-20261127/*-mode-*.log`.

## Windows Stricky 1.2.0 사용 흐름 (2026-11-27)

- 하단 투명도·글자 크기 이름과 값, ×/Alt+F4 삭제 확인, 마우스로 색조·채도·명도를 선택하는 색상표, RGB 동기화·32색 견본, 글씨체 선택·미리보기·저장을 추가했습니다. 기존 v1 데이터는 선택 필드 fontFamily가 없어도 읽습니다.

## S3776 수정 검증 (2026-11-26)

제공된 GitHub Actions 로그에서 패키지 복원은 성공했으나 `SingleInstanceService.Signal()`이 인지복잡도 7로 측정돼 임계값 5를 초과했습니다. 루프 안의 `try/catch`와 성공 분기가 함께 중첩된 것이 원인입니다. 예외 처리를 `TryActivate()`로 분리하고 `Signal()`은 최대 3회 반복과 성공 시 반환만 담당하도록 수정했습니다. 연결·응답 제한 시간, 활성화 응답 확인 및 재시도 대상 예외는 유지합니다. S3776 임계값과 오류 설정은 변경하지 않았습니다.

- 로컬 Framework MSBuild x86/x64 Release 빌드 성공, 회귀 테스트 각각 **21 통과 / 0 실패**.
- 로컬 VS MSBuild `/restore`는 양쪽 모두 사용자 NuGet 설정 폴더 접근 거부로 실패했습니다. 수정 후 Sonar 분석 및 원격 Actions 재실행은 미검증입니다.
- 실행 로그: `TestResults/s3776-fix/` (Git 제외).

## IPC 수정 검증 (2026-11-26)

GitHub Actions에서 x86 단일 인스턴스 IPC 회귀 테스트가 실패한 로그를 확인했습니다. 연결 직후 클라이언트가 종료되던 흐름을 활성화 콜백 실행 후 1바이트 응답을 기다리도록 변경했습니다. 연결과 응답 대기는 각각 800ms, 재시도는 최대 3회입니다. 클라이언트가 응답 전에 시간 초과로 연결을 끊어도 서버는 다음 연결을 계속 받습니다. 테스트는 GUID로 분리한 사용자/세션별 Mutex와 Pipe를 사용하므로 실행 중인 앱과 충돌하지 않습니다.

- 로컬 Framework MSBuild x86/x64 Release 빌드 성공, 콘솔 회귀 테스트 각각 **21 통과 / 0 실패**.
- 활성화 완료 확인, 응답 시간 초과 후 재연결, 별도 프로세스 10회 연속 활성화를 검증했습니다.
- 테스트 어셈블리에 `AssemblyVersion`을 추가해 로그의 S3904 경고 원인을 제거했습니다. 분석기 재실행은 미완료입니다.
- VS MSBuild `/restore`는 x86/x64 모두 사용자 NuGet 설정 폴더 접근 거부로 실패했습니다. 아래의 설치된 Framework 참조 방식으로 빌드했으며, 정식 복원·Sonar 분석·원격 Actions 재실행은 미검증입니다.
- Windows 7 및 OS별 수동 검증은 수행하지 않았습니다. [호환성 체크리스트](compatibility.md)의 미검증 상태를 유지합니다.

정식 빌드 명령은 `scripts/build.ps1`입니다. `/restore`로 공식 4.8 참조 어셈블리와 빌드 전용 Sonar 분석기를 준비하고 양쪽 플랫폼의 회귀 테스트를 실행합니다. `SonarLint.xml`은 S3776 임계값 5, `.editorconfig`는 초과 시 오류를 지정합니다. 이 호스트에는 VS Roslyn 도구가 없고 NuGet·Microsoft 다운로드 서버 연결도 차단돼 있습니다. 분석기 통과나 정식 배포 빌드 성공을 주장하지 않습니다.

실제로 통과한 제한적 로컬 명령:

```powershell
foreach ($platform in @('x86', 'x64')) {
    & "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe" StickyNote.sln /m /p:Configuration=Release /p:Platform=$platform /p:FrameworkPathOverride="$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319"
    & ".\tests\StickyNote.Tests\bin\$platform\Release\StickyNote.Tests.exe"
}
```

이 경로는 설치된 런타임 어셈블리를 참조하며 Sonar 분석기를 실행하지 않습니다. CI의 공식 참조 어셈블리 빌드와 대상 OS 실행을 대체하지 않습니다.

회귀 범위: UTF-8/UTC JSON, 스키마 경계, 필드 검증, 원자적 저장·정상본, 잠금 실패, 손상 복구·덮어쓰기 차단, 동시 revision, 백업·복원 트랜잭션, journal 재생, 화면 좌표 보정, debounce, 메모 작업·검색, 언어 리소스, HWND 모드 전환, 단일 인스턴스 IPC, 손상 바이트 원본 보존, dispatcher 스냅샷 격리.

기존 `Expected 10, got 3` 오류는 동일한 시스템 시각으로 백업명이 충돌한 결과입니다. UTC+GUID 파일명으로 수정했고 고정 시각에서 연속 백업이 별개로 남으며 최종 10개가 보관되는지 검사합니다. 별도의 테스트 프레임워크나 런타임 패키지는 사용하지 않습니다.

격리 앱은 `--diagnostic-data-directory`가 있는 Debug 빌드로 실행했습니다. 확인 후 테스트 프로세스만 종료했습니다. 실제 메모 폴더·자동 실행 레지스트리·Explorer·OS 구성은 변경하지 않았습니다. 테스트 데이터와 진단 출력은 무시되는 `TestResults/`에 둡니다.

설치 파일은 런타임 포함·기존 Framework 건너뛰기·UAC 취소·재부팅·오프라인 설치·제거 후 데이터 보존을 별도 확인해야 합니다. 대상 OS와 DPI·IME·트레이·Desktop의 실제 표시 검증은 [호환성 체크리스트](compatibility.md), Shell 제약은 [Desktop 문서](desktop_widget.md)를 따릅니다.
